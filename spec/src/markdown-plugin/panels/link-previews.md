# Link Previews

Backlinks and Outgoing Links share one app-bound preview and editing contract.
Ordinary internal links rendered by Mira use the same adapter and appearance but
remain Mira-owned.

## Requirements

| ID | Requirement |
| --- | --- |
| LN-MD-026 | The Markdown package MUST adapt the Lapis vault, metadata cache, workspace navigation, and `EmbedRegistry` to Mira's public `MiraFileAdapter`. Reading mode and live preview MUST receive that adapter so ordinary internal note links and embeds use Mira's portable preview surfaces. Backlinks and Outgoing Links hover and focus previews MUST compose the same public app-bound `FileEmbed` inside Design Core Hover Card and Scroll Area rather than maintaining a private full-document preview. Their overlay defaults to 26rem wide capped by the viewport instead of inheriting the generic Hover Card width. The complete mention row remains clickable and focusable through the Trigger child snippet. Bits UI `LinkPreview` owns the 700ms open delay, 300ms close delay, keyboard-focus lifecycle, safe pointer corridor, and collision shift and flip behavior; Lapis MUST NOT add manual timers, conditional mounting, a zero-width anchor, or a forced side. The overlay follows its trigger document through Design Core and remains topmost and interactive across constrained editors and floating panes. The adapter resolves links relative to `sourcePath`, reads and watches Markdown files, lists files and headings, opens files through the workspace, renders registered non-Markdown embeds and image resources with cleanup, and declines unowned file types so Mira can fall back to portable Markdown rendering. Generic and direct embeds preserve `internal-embed`, `markdown-preview-surface--embedded`, `markdown-embed-surface`, and `data-markdown-embed`; the LN-MD-029 editable panel card uses embedded Markdown identifiers without fabricating the generic guided `internal-embed` wrapper. |
| LN-MD-027 | Ordinary internal links rendered by Mira in reading and live-preview modes MUST retain the Lapis `MiraFileAdapter` resolution, lazy preview, and navigation path while delegating timing, safe pointer handoff, owner-document mounting, collision placement, appearance, and topmost cross-pane paint to Mira's portable Bits UI `LinkPreview`. Lapis MUST NOT add a portal wrapper, source alias, or clipping workaround. |
| LN-MD-028 | The Lapis `MiraFileAdapter` MUST provide `writeMarkdown` through `app.vault.modify` for an existing Markdown file and reject missing or non-Markdown targets. Ordinary Mira internal-link previews become editable automatically. Backlinks and Outgoing Links opt their public app-bound `FileEmbed` into the same Mira `EditableMarkdownPreview` lifecycle and pin their Design Core Hover Card while it edits. A plain click on non-interactive rendered content enters toolbar-free live preview, writes debounce for 500ms, and every configured exit flushes before returning to preview. Escape closes the card after a successful flush, while failed writes retain an accessible dirty editor. Direct document `![[file]]` embeds remain read-only. Lapis retains storage and Hover Card composition ownership without copying Mira's editor, persistence coordinator, click filtering, or CodeMirror pipeline. |
| LN-MD-029 | Ordinary Mira note previews and Backlinks and Outgoing Links previews MUST share a minimal content-first treatment: no visible filename or path header, all-round Markdown inset space that keeps heading and list disclosure controls visible, and a two-pixel focus-ring border while editing. The panel `FileEmbed` omits the embedded-note guide in editable-card mode and keeps only its open-note action in a sticky top-right row so it remains visible while content scrolls and content never paints beneath it. In edit mode, the fixed preview viewport and content wrapper constrain `FileEmbed` to the available height so CodeMirror owns vertical scrolling; the outer Scroll Area MUST NOT clip an unconstrained editor or introduce a second scrollbar. Editing cards ignore hover departure and focus movement; outside pointer interaction flushes and dismisses only after persistence succeeds, while Escape remains the keyboard dismissal and save failures keep the dirty editor open. |
| LN-MD-030 | Ordinary Mira note previews and Backlinks and Outgoing Links `FileEmbed` previews MUST resolve the same Lapis-aligned Mira appearance. Mira-owned portaled previews carry the effective `obsidian` theme inherited by their document trigger, while editable Lapis `FileEmbed` roots establish that theme explicitly. The local Obsidian alias layer maps Mira accent, focus, soft-accent, selection, and accent-foreground variables to design-core's Lapis semantic tokens. Preview-only all-round Markdown padding is scoped to the rendered editable-preview branch and MUST NOT inset the nested frontmatter widget after CodeMirror enters live edit. |
