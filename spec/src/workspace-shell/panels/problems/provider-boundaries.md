# Search result and Problems provider boundaries

Shared Notes-session extraction preserves the App-owned Problems registry and
recovery actions. Startup Retry is a host startup state, not a diagnostic or a
replacement Problems view. Failed leave retains the existing App and its
editing recovery ownership; admitted native Chat/Repository factories do not
change diagnostic payloads, navigation or persistence authority.

Generic plugin SVG and pack registrations follow LN-PLUG-123 independently of
diagnostic collections. File-view artwork is presentation metadata, never a
Problems diagnostic payload, permission or recovery action. Existing diagnostic
severity and label presentation remain Design Core-owned.

The shared [native editing-intent foundation](../../../architecture/native-editor-intents.md)
returns admission, dirty and uncertain-transition state to the owning App. This
source port does not create a Problems collection or discard an abandoned
writer. Captured-generation recovery through existing Problems actions remains
a separately qualified host contribution.

LN-SRCH-051 adds query-result sources to the owning App. These registrations
return navigation targets and presentation data only. They do not contribute
Problems, diagnostic collections, editor markers, fixes or permissions.

The diagnostic integration contracts in [Integration contracts](core-contract.md)
remain unchanged. This boundary confirmation accompanies the additive Plugin and
App registry exports; it does not qualify any new diagnostic behavior.
Declinable Markdown embedders register on `EmbedRegistry` and do not contribute
Problems, diagnostic collections, editor markers, or fixes.

Indexing contribution unavailability under LN-CORE-005 remains service status
and notification data. Selecting the native background port does not introduce
a diagnostic model, callback transport or competing Problems presentation.

Shared native Search selection failures remain indexing status/notification
data. Observer sharing does not add a Problems collection or competing panel.

The [admitted native Task observer](../../../architecture/rust-task-host-port.md#ln-core-014) retains typed failures, partial outcomes and request identity for host adapters. Diagnostic collection ownership and presentation continue through the existing Problems integration contract. A raw Task outcome is service data; an explicit host-owned contribution supplies any navigation or recovery action.
